# Finedu — Telegram Mini App: дизайн-спецификация

Дата: см. git log. Статус: одобрено владельцем продукта (см. диалог брейнсторминга).

## 1. Назначение и аудитория

- **Владелец:** физическое лицо (разработка для себя).
- **Цель:** интерактивное и увлекательное обучение детей и студентов финансовой
  грамотности.
- **Аудитория:** любой человек, интересующийся финансовой грамотностью; открыто
  всем, без регистрации.
- **Первые 30 секунд:** пользователь сразу видит и может просматривать контент
  (темы → уроки), без каких-либо барьеров входа.
- **Контент:** создаётся с нуля, по образцу изученных англоязычных проектов
  (Khan Academy — структура «тема → уроки», Clever Girl Finance — дружелюбный
  тон, Visa Practical Money Skills — геймификация квизов).

## 2. Платформы запуска

- **Telegram:** открывается через бота (BotFather настраивает владелец) как
  Telegram Mini App, полноэкранный режим.
- **Обычный браузер:** то же приложение открывается и в браузере по адресу
  `https://moneyedu.ru`. В браузере доступен только просмотр (темы, уроки,
  квизы в режиме «без сохранения»). Вкладка «Прогресс» в браузере показывает
  заглушку «Откройте в Telegram, чтобы сохранять прогресс».

## 3. Информационная архитектура — нижнее меню (4 вкладки)

Порядок и вкладка по умолчанию определены и одобрены на этапе брейнсторминга:

1. **Темы** (вкладка по умолчанию) — каталог тем-курсов карточками (иконка,
   название, число уроков, прогресс-бар). Тап по карточке → список уроков
   темы. Тап по уроку → содержимое урока.
2. **Квизы** — отдельные быстрые квизы (не привязаны к прохождению урока),
   список по темам, кнопка «Начать», сохраняется лучшая попытка.
3. **Прогресс** (только в Telegram, требует telegram_id) — общий процент
   прохождения, прогресс по каждой теме, бейджи/достижения.
4. **О проекте** — описание приложения, ссылка на политику
   конфиденциальности, переключатель уведомлений, номер версии.

Макеты всех экранов утверждены визуально в ходе брейнсторминга (хранятся в
`.superpowers/brainstorm/<session>/content/*.html` для истории; не являются
production-кодом).

## 4. Экраны и переходы

- **Темы → Список уроков темы**: показывает все уроки темы по порядку;
  пройденные — галочка + результат квиза, текущий — активен, следующие —
  приглушены (визуально заблокированы, но не технически — доступны по тапу).
- **Урок**: состоит из коротких шагов-карточек (текст + эмодзи/картинка),
  навигация «Далее →», прогресс-бар шагов сверху.
- **Квиз урока**: после последнего шага урока — 2-3 вопроса с мгновенной
  обратной связью (верно/неверно подсвечивается сразу).
- **Квиз из вкладки «Квизы»**: тот же механизм вопрос-ответ, не привязан к
  открытию урока.
- **Прогресс**: агрегирует данные по всем темам и бейджам пользователя.
- **О проекте**: статический контент + ссылка на политику конфиденциальности.

## 5. Технический стек

- **Backend:** FastAPI (Python), один процесс, отдаёт API и собранный
  фронтенд.
- **Frontend:** React + Vite + React Router, собирается в статику.
- **База данных:** SQLite, один файл на диске сервера.
- **Бот:** отдельный скрипт/процесс на том же сервере (python-telegram-bot
  или прямые HTTP-вызовы к Telegram Bot API) — отправляет уведомления.
- Никаких ORM-фреймворков, очередей, контейнеризации и т.п. — минимум
  зависимостей согласно принципу «проще — надёжнее» (п. 11 требований).

## 6. Модель данных

```
Topic (тема):
  id, title, description, icon, order, is_published

Lesson (урок):
  id, topic_id, title, order, content (JSON: список шагов —
    {type: "text"|"image", ...}), is_published

Quiz (квиз):
  id, lesson_id (nullable — null = отдельный квиз вкладки "Квизы"),
  title, questions (JSON: [{question, options[], correct_index}]),
  is_published

Progress (прогресс, только для telegram-пользователей):
  telegram_id, lesson_id, completed_at,
  quiz_id, quiz_score, last_activity_at

User (пользователь):
  telegram_id (первичный ключ), created_at, notifications_enabled
```

Никаких имён, телефонов, email — единственный идентификатор это
`telegram_id`, полученный из проверенного `initData`.

## 7. API (основные маршруты)

- `GET /api/topics` — список тем (публичный, без авторизации).
- `GET /api/topics/{id}/lessons` — уроки темы (публичный).
- `GET /api/lessons/{id}` — содержимое урока (публичный).
- `GET /api/quizzes` / `GET /api/quizzes/{id}` — квизы (публичный).
- `POST /api/progress` — сохранить прогресс. Требует заголовок с `initData`;
  сервер проверяет подпись и извлекает `telegram_id` — тело запроса никогда
  не передаёт `telegram_id` напрямую от клиента.
- `GET /api/progress/me` — прогресс текущего пользователя (то же самое:
  `telegram_id` берётся из проверенного `initData`, не из query/body).
- `POST/PUT/DELETE /api/admin/*` — управление темами/уроками/квизами,
  рассылки. Требует проверенный `initData` **и** совпадение полученного
  `telegram_id` с `ADMIN_ID` из конфигурации сервера.

## 8. Безопасность админки (ключевое требование)

Алгоритм проверки на сервере для каждого запроса к `/api/admin/*`:

1. Принять заголовок `X-Telegram-Init-Data` (сырая строка initData).
2. Пересчитать HMAC-SHA256 подписи по алгоритму Telegram, используя
   `BOT_TOKEN` из файла настроек сервера (никогда — из кода/репозитория).
3. Если подпись не совпадает — вернуть `403`, дальше не продолжать.
4. Если подпись верна — распарсить `telegram_id` из проверенных данных.
5. Сравнить `telegram_id` с `ADMIN_ID` из файла настроек. Если не совпадает —
   `403`.
6. Только после обоих успешных шагов — выполнить операцию.

Данным, присланным клиентом без валидной подписи (включая произвольный JSON
с `telegram_id` в теле запроса), сервер не доверяет никогда — `telegram_id`
для принятия решений берётся **только** из криптографически проверенной
initData, не из тела запроса.

### Обязательные автотесты (доказательство защиты)

1. Запрос без `initData` / с пустой строкой → `401` или `403`, нет доступа.
2. Запрос с синтаксически валидной, но неверно подписанной `initData`
   (подделанный HMAC) → `403`.
3. Запрос с валидной подписью, но `telegram_id` ≠ `ADMIN_ID` → `403`.
4. Запрос с валидной подписью и `telegram_id` = `ADMIN_ID` → `200`, операция
   выполняется.

Тесты на `pytest`, входят в CI/процесс деплоя — деплой недопустим при красных
тестах.

## 9. Админ-панель — функциональность

Доступна только владельцу (см. раздел 8). Возможности:

- CRUD тем, уроков, квизов (создание/редактирование/публикация-черновик/
  порядок отображения).
- Простая статистика: число прошедших тему/урок.
- Форма рассылки уведомлений: «всем» или «тем, кто не заходил N дней».

## 10. Уведомления

Два триггера для MVP:

1. **Автоматическое напоминание**: если пользователь не открывал приложение
   N дней (по умолчанию 3) — бот присылает сообщение с предложением продолжить
   конкретный незавершённый урок.
2. **Ручная рассылка** из админ-панели: «всем» или «тем, кто не заходил N
   дней», свободный текст.

Пользователь может отключить уведомления переключателем на вкладке
«О проекте» (`notifications_enabled` в таблице User).

## 11. Персональные данные

- Собираемые данные: только `telegram_id`, дата создания записи, статистика
  прогресса. Никаких имён/телефонов/email на этапе MVP.
- Согласие: подразумевается фактом открытия Mini App через Telegram; отдельная
  галочка согласия не требуется, пока не появятся формы с вводом личных данных
  (если появятся — галочка и ссылка на политику добавляются туда отдельно).
- Политика конфиденциальности: шаблон готовится отдельным документом
  (`docs/privacy-policy-template.md`), ссылка на неё — на вкладке «О проекте».
  Данные хранятся на сервере в России (cloud.ru).
- Команда боту `/delete_my_data` удаляет запись User и весь Progress этого
  telegram_id.

## 12. Инфраструктура и деплой

- **Сервер:** cloud.ru (российский провайдер — соответствует требованию
  хранения данных в РФ).
- **Домен:** `moneyedu.ru`, зарегистрирован на Timeweb; DNS A-запись указывает
  на IP сервера cloud.ru.
- **TLS:** бесплатный сертификат Let's Encrypt (`certbot`), автопродление.
- **Процесс:** FastAPI запускается под `systemd` (автоперезапуск при падении
  и перезагрузке сервера), Nginx — реверс-прокси с терминацией TLS.
- **Тестовый контур до переноса на прод:** локальный запуск + Cloudflare
  Tunnel/ngrok для проверки в реальном Telegram-клиенте без домена/сервера.
- **Секреты:** `BOT_TOKEN` и `ADMIN_ID` — только в файле `.env`/`config` на
  сервере cloud.ru, не попадают в код, git-репозиторий или переписку.
  `.env` обязательно в `.gitignore`.

## 13. Языки

Интерфейс — русский (единственный язык на старте).

## 14. Критерии готовности

- Приложение открывается в Telegram на телефоне на весь экран.
- Все 4 вкладки работают, переходы плавные (React Router + анимации).
- Контент (минимум 2-3 темы с уроками и квизами) на месте.
- Admin-панель недоступна без валидной подписи initData + ADMIN_ID — что
  подтверждают 4 обязательных теста (раздел 8).
- Приложение открывается и в обычном браузере в режиме просмотра.
- Есть инструкция по деплою и обновлению контента (будет частью
  implementation-плана).

## 15. Явно вне рамок MVP (зафиксировано, чтобы не расползалось)

- Видео, карточки-статьи без квизов, игровые симуляции — только уроки+квизы.
- Регистрация с именем/телефоном/email.
- PostgreSQL/масштабирование под высокую нагрузку.
- Автоматическое уведомление о публикации новой темы (только ручная рассылка
  на старте).
- Мультиязычность (только русский).
